1. 端到端总览：输入 → L3 → 并行 L2/L1 → L0 → 输出

flowchart TB
  S([开始：选择网表文件]) --> OPT[可选设置：原理图图片、DeepSeek/千问配置、阈值、超时、温度、域并发数、输出目录]
  OPT --> LOAD{输入格式？}
  LOAD -->|EasyEDA .enet| ENET[解析器件、位号、值、封装、引脚与网络]
  LOAD -->|标准 JSON| JSON[校验 components/nets、器件位号唯一、网络端点有效]
  ENET --> NORM[标准化 netlist + topology；保存 normalized_netlist.json]
  JSON --> NORM
  NORM --> IMG{提供原理图图片？}
  IMG -->|是| IMGCHK[检查文件存在、图片 MIME、大小 ≤ 8 MB]
  IMG -->|否| L3
  IMGCHK --> L3[L3：整份网表按电压阈值划分]
  L3 --> L3PROMPT[生成 L3 提示词并保存输入、请求]
  L3PROMPT --> DRY{Dry-run？}
  DRY -->|是| PLACEHOLDER[不调用模型：临时全部归入 low_voltage，并标记不确定]
  DRY -->|否| DS3[DeepSeek 分析工作电压与网络证据]
  DS3 --> V3[解析 JSON 并校验：覆盖全部器件、唯一归属、仅高/低压、置信度及网络合法]
  V3 -->|格式/结构可修复| REPAIR3[按错误信息请求一次修复；特殊模型 HTTP 400 时回退普通请求]
  REPAIR3 --> V3
  V3 -->|通过| SAVE3[保存 L3 JSON/CSV 与模型记录]
  V3 -->|仍失败/接口异常| ERR[记录 flow_error.json，流程结束]
  PLACEHOLDER --> SAVE3
  SAVE3 --> DOMAINS
  DOMAINS[按 L3 结果生成非空电压域任务] --> WORKERS[线程池执行：默认最多 2 个域并发，可设 1–4；每域仅处理自身器件与连接]
  WORKERS --> L2[L2：综合功能域划分（每个 L3 域各跑一次）]
  L2 --> L1[L1：在最终 L2 边界内生成细功能簇]
  L1 --> MERGE[合并各域结果并建立 L3→L2→L1 嵌套层级]
  MERGE --> L0[L0：每个器件创建独立单器件簇；识别连接器标记]
  L0 --> CHECK{全局覆盖校验：每个输入器件是否恰好一次？}
  CHECK -->|否/重复或遗漏| ERR
  CHECK -->|是| WRITE[写出 hierarchy.json、逐器件总表、L3/L2/L1/L0 分层 CSV、run.json]
  WRITE --> E([完成])

2. L2 展开：功能识别、确定性算法、DeepSeek 补簇 / 千问识图分支

flowchart TB
  A[输入：当前 L3 域的器件/网络子网表；可选原理图] --> B[标准化网表与拓扑；保存 L2 输入文件]
  B --> C{Dry-run？}
  C -->|是| C1[不调用模型：生成待识别占位功能标注]
  C -->|否| D[DeepSeek：为本域所有器件识别功能类别、说明、证据、置信度]
  D --> E{标注是否完整有效？}
  E -->|否| E1[按校验错误修复一次：每个已知器件恰好一条标注]
  E1 --> E2{修复后有效？}
  E2 -->|否| X[报错并停止本次流程]
  E2 -->|是| F[保存功能标注 JSON/CSV]
  E -->|是| F
  C1 --> F
  F --> G[本地确定性算法：校验 topology；推导网络语义、器件角色、规则命中与电路 motif]
  G --> H[构造候选 L2 粗功能域/锚点；算法运行时不调用 LLM，不学习或提升软规则]
  H --> I[提取锚定大器件域、未归属小器件；补齐算法漏出的器件]
  I --> J[筛选：有锚定目标时，未归属小器件进入 eligible；无目标时保留为 no-target；未归属大器件不送补簇]
  J --> K{Dry-run？}
  K -->|是| K1[跳过 DeepSeek 补簇和千问识图；保留算法归属/审计信息]
  K -->|否| L{有原理图 + 锚定大器件域 + 候选小器件？}
  L -->|是| M[跳过冗余 DeepSeek 补簇；准备千问请求]
  M --> N[千问：只看原理图，为候选小器件选择已有锚定大器件 L2 域]
  N --> O{结果覆盖完整且目标合法？}
  O -->|否| O1[带校验错误请求修复一次]
  O1 --> O2{修复后有效？}
  O2 -->|否| X
  O2 -->|是| P[以千问归属更新候选器件；不允许新建域或改动锚定器件]
  O -->|是| P
  L -->|否| Q{eligible 小器件非空？}
  Q -->|是| R[DeepSeek 补簇：结合功能标注、网络连接与锚定域上下文，形成独立辅助 L2 簇]
  R --> R1{覆盖 eligible 且 JSON/网络证据有效？}
  R1 -->|否| R2[按错误请求修复一次] --> R3{修复后有效？}
  R3 -->|否| X
  R3 -->|是| T[合并确定性锚定域与补簇结果]
  R1 -->|是| T
  Q -->|否| Q1[不补簇；无目标小器件保留为可审计的未锚定域]
  P --> U[保存千问请求/响应与可见证据]
  U --> V[千问结果替换候选器件旧归属；合并锚定域]
  V --> Z
  T --> Z
  K1 --> Z
  Q1 --> Z
  Z{L2 最终完整性校验：所有器件均覆盖一次、无未知/重复？}
  Z -->|否| X
  Z -->|是| OUT[写 l2_final_result.json、l2_final_assignments.csv、flow_manifest.json；记录阶段耗时和逐次 API 往返/重试统计]
  OUT --> NEXT[交给 L1：最终 L2 域 + DeepSeek 功能标注]

千问只给尚未进入大器件锚定域的小器件归属；不能新建 L2 域、不能重分大器件。若其完整归属会覆盖 DeepSeek 补簇结果，代码会跳过那次不会被采用的 DeepSeek 请求。若没有可用锚定目标，则不会要求模型凭空发明目标域。

3. L1、L0、校验、计时与文件输出

flowchart TB
  A[输入：本 L3 域的规范网表 + 最终 L2 域 + L2 功能标注] --> B[校验 L2 覆盖与功能标注；构造器件-网络映射和直接连接关系]
  B --> C[只在同一个 L2 域内枚举候选器件对；有锚点时限制在锚点一跳连接前沿]
  C --> D[拓扑分：直接共网、共享网络数、锚点范围]
  C --> E[功能分：功能类别精确/词项相似度 + 功能说明相似度；未知功能降权]
  D --> F[加权聚合分数]
  E --> F
  F --> G{达到候选阈值？}
  G -->|否| I[该对不成簇]
  G -->|是| H[按分数从高到低贪心选择；成员已被选、跨域或冲突者拒绝]
  H --> J[选中的不重叠器件对形成 L1 功能簇]
  I --> K[未被选中的器件各自形成 L1 单成员簇；锚点未成对时也单独保留]
  J --> K
  K --> L[L1 输出：簇 ID、成员、来源、聚合/拓扑/功能分数]
  L --> M[展开 L0：每个 L1 成员逐个创建唯一 L0 单器件簇]
  M --> N[连接器识别：J/P/CN/CON/USB 位号前缀，或类型/名称/描述/封装含连接器等标记]
  N --> O[连接器写 True；非连接器留空 / null（不填 False）]
  O --> P{全局检查：每个输入元件在 L3、L2、L1、L0 均覆盖一次？}
  P -->|否| ERR[失败：写 flow_error.json；指出遗漏/未知/重复归属]
  P -->|是| OUT[写完整层级 hierarchy.json + 总分配表 hierarchical_assignments.csv]
  OUT --> CSV[分别输出 L3_assignments.csv、L2_assignments.csv、L1_assignments.csv、L0_assignments.csv]
  OUT --> TIME[run.json：各层时间、总时间、域并发数、数量统计、L2 逐域/逐模型调用诊断]
  CSV --> END([完成])
  TIME --> END

4. 时间统计口径与输出文件

L3从载入/标准化网表至 L3 划分完成，包含 L3 模型等待。
L2每个 L3 域的 L2 综合流程耗时：DeepSeek 功能识别、确定性算法、可触发的补簇/千问识图及写文件。
L2 并行口径total_seconds 为跨域耗时之和；wall_clock_seconds 为并发后的实际等待时间。
L1 / L0L1 按 L3 域计时；L0 计创建单器件簇和连接器标记的本地耗时。
接口耗时L2 manifest 记录每次请求客户端完整往返时间、重试次数/等待、请求响应字节和服务端返回 usage；不是服务端纯推理时间。
失败留痕主流程异常写 flow_error.json；阶段产物保留在指定输出目录，成功后写 run.json。
文件内容
normalized_netlist.json统一格式的器件、引脚、网络输入。
l3/L3 的输入、请求、模型响应和高/低压域结果。
domains/<L3域>/l2/功能标注、算法拓扑/结果、补簇或视觉请求、L2 最终结果及阶段 manifest。
domains/<L3域>/l1/配对分数、L1 结果和分配 CSV。
hierarchy.json完整嵌套树、逐器件归属、分层时间和覆盖状态。
hierarchical_assignments.csv器件到 L3/L2/L1/L0 的总表和 is_connector。
L3_assignments.csv 等四份 CSV每层各自逐器件结果和该层耗时；L0 表另有连接器标记。
run.json本次总耗时、每层耗时、域数量、模型调用诊断和产物索引。
图中流程边界按当前代码实现整理。单次模型 JSON/覆盖错误有显式修复分支；若修复仍失败或接口请求失败，最外层流程记录错误并停止，不会把失败结果当作成功划分。
